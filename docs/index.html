Getting started

Run one small experiment first.

You do not need to configure every Brali module. Pick one useful practice, try it in real life, capture a small signal, and decide what to do next.

1. Choose one starting protocol

Start with the seven flagship protocols: one curated starting point for each Life Area. Pick the one that matches a real situation you want to improve now, not the area you think you should optimize someday.

2. Make the action small enough to do

Read the Protocol Summary and choose the smallest version you can realistically try. Add the action to Brali as a task, focus session, challenge, or simple plan. The goal is to make the experiment concrete, not to build a perfect system around it.

3. Do it before adding more structure

Try the action once. Avoid adding several routines, metrics, tags, and goals before you have any real feedback. One completed experiment gives you more useful information than a beautifully configured dashboard you never use.

4. Capture one signal

Use the protocol's check-in, a short journal note, or one relevant metric. Record only enough to answer a practical question: did this happen, what did I notice, and was it useful enough to try again?

5. Review and choose

After a few attempts or at the protocol's natural review point, make one decision: keep it, change it, pause it, or replace it. Brali is meant to help you learn from your own record rather than maintain streaks for their own sake.

Then expand only when it helps

If the first experiment is useful, explore its Life Area, related protocols, or the complete Growth Library. Add more tracking only when it improves a decision you actually need to make.

Your first Brali loop

Choose → Practice → Check in → Review → Keep or change. That loop is enough to start.
