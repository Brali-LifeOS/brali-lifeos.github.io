# Brali data 1.0.0

Brali data 1.0.0 is the first stable, versioned baseline of the Brali knowledge platform. It freezes the public machine-readable surface so researchers, developers, and AI systems can cite and pin a specific snapshot instead of following a moving `main` branch.

## What is included

- Canonical knowledge datasets listed by `life-os/datasets/manifest.json`.
- Stable canonical IDs and multilingual alias metadata.
- Ontology coverage and the prioritized migration queue.
- Evidence states, review queue metrics, and reviewed Evidence Decisions.
- Trusted Protocol Feed and retrieval benchmark output.
- The complete static Knowledge API v1 surface and OpenAPI contract.
- Agent registry plus the machine-readable integration metadata included by the canonical manifest.
- `CITATION.cff`, license and licensing terms, source/evidence policies, versioning rules, this release note, a release manifest, and SHA-256 checksums.

## Trust model

Normal trusted retrieval is limited to records whose evidence state is `reviewed` or `practical`. Records marked `pending-review` or `restricted` remain visible as editorial state but must not be presented as trusted recommendations. Research discovery records are leads, not evidence. Evidence Decisions record the bounded claim that was reviewed, unsupported or overstated claims, limitations, and the editorial outcome.

## Reproducibility

The immutable release identifier is `data-v1.0.0`. The release workflow rebuilds the site data, runs the full repository quality gate, packages the complete release payload, and verifies every packaged file against `release-manifest.json` and `SHA256SUMS` before publishing release assets.

Consumers should verify the archive checksum first, then use the packaged `SHA256SUMS` for individual files. Long-lived integrations should pin this release rather than `main`.

## Known limitations

- Brali still contains a large legacy long tail. Only part of the library has flagship-level editorial depth, so raw entry count must not be treated as a quality metric.
- The retrieval benchmark is intentionally small and is a regression baseline, not proof of broad real-world agent performance. A larger Agent Evaluation Suite is planned separately.
- Russian support is currently an identity/alias pilot, not a full translation of the corpus.
- The Knowledge API is a static read-only contract. The MCP implementation is also read-only and currently runs from a checkout/build rather than a hosted managed service.
- Health and mental-health material requires especially conservative interpretation. Brali is a practical knowledge resource, not a diagnostic or treatment service.
- A `watch` or other non-promoting Evidence Decision can inform research direction without justifying a recommendation.

## Citation and license

Use the packaged `CITATION.cff` for citation metadata. The packaged `LICENSE` and `LICENSING.md` are authoritative for reuse terms. Source-level third-party rights and attribution requirements still apply where identified by Brali source metadata.
