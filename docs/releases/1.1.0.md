# Brali data 1.1.0

Brali data 1.1.0 is the first distribution-focused release of the evidence-aware practical-knowledge platform. It supersedes the August 1.0.0 baseline with the current trusted corpus, stronger research/evidence decisions, portable Agent Skills, reproducible evaluation artifacts, and release metadata prepared for external dataset/archive mirrors.

## What changed

- Current canonical Topics, Hacks, Protocols, evidence states, provenance and aliases are pinned together under a new immutable data version.
- Brali Bench packages the checked evaluation cases, results, comparison layers and reproduction contract as a reusable artifact.
- MCP source now shares one tool/trust factory across local stdio and deployment-ready Streamable HTTP transports.
- The `brali-life-os` Agent Skill has a dedicated single-router distribution package so external registries do not need 900+ generated skill entries.
- The release bundle now contains a Hugging Face-ready Dataset Card and explicit external-distribution placeholders that remain null until provider-visible artifacts exist.
- `CITATION.cff` remains the durable citation metadata source for archive integrations such as Zenodo.

## Trust model

Normal trusted retrieval is limited to records whose evidence state is `reviewed` or `practical`. Records marked `pending-review` or `restricted` must not be silently promoted into recommendations. Research discovery candidates are leads, not evidence. Evidence Decisions preserve bounded reviewed claims and unsupported/overstated boundaries.

Agent and API consumers should preserve canonical IDs, canonical URLs, evidence state, provenance and deliberate no-answer behavior. A protocol being `reviewed` does not imply universal efficacy; `practical` does not imply external scientific validation.

## Brali Bench

The release includes Brali Bench as a deterministic retrieval/grounding evaluation artifact. It measures routing/retrieval, evidence boundaries, provenance, safety/no-answer behavior and a usefulness proxy across the checked suite. It is not a benchmark of an unpinned language model and should not be presented as one.

## Distribution

The immutable GitHub release is the source artifact. The release root includes a Dataset Card suitable for mirroring to Hugging Face. Zenodo-compatible citation metadata is provided through `CITATION.cff`.

External URLs, downloads, registry installs, DOIs and citations are not considered live merely because the release is prepared for them. Record those only after the external provider exposes a verifiable public artifact.

## Known limitations

- Brali's corpus is curated practical knowledge, not medical, legal, financial, or other professional advice.
- Coverage is intentionally uneven; deliberate no-answer behavior is preferred over stretching an adjacent record.
- The remote MCP implementation is deployment-ready source code, not proof that Brali currently operates a hosted remote MCP endpoint.
- GitHub Agent Skills, ClawHub, Hugging Face and Zenodo each have independent publication/authentication steps and provider-side availability.
- Brali Bench evaluates the repository retrieval/grounding contract rather than general language-model capability.
- Public reuse remains subject to CC BY-NC-SA 4.0 and the repository's commercial-use boundary.

## Reproducibility

Pin `data-v1.1.0`, verify `SHA256SUMS`, use `release-manifest.json` as the inventory, and cite the pinned release rather than a moving `main` snapshot.
