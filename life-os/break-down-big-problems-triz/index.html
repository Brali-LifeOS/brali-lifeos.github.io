Decompose a Hard Problem with TRIZ-Inspired Contradictions

Expose the conflict before optimizing around it.

Protocol summary · practical

Try this

State the unwanted outcome, map the main parts and interactions, write the trade-off as two requirements that appear to conflict, generate separation or redesign options, choose a reversible check, and record which assumption or constraint changed.

Check-in: What contradiction did I expose, what separation or redesign did I check, and did it remove the conflict or only move it elsewhere?

Evidence: Practical guidance; no evidence-like claim is detected in the current source record.

Some problems stay hard because the current design treats a trade-off as fixed. A TRIZ-inspired pass asks whether conflicting requirements can be separated or whether the system can be changed so they no longer compete in the same way.

1. State the unwanted result

Describe what happens now and where it appears in the system. Separate symptoms from constraints you know are real.

2. Write the contradiction

Express the conflict as two requirements: what must improve and what must not become worse. Add the condition under which each requirement matters.

3. Separate, redesign, and check

Ask whether the requirements can be separated by time, place, condition, component, role, or state. Use a small reversible check and inspect side effects so the conflict is not merely moved elsewhere.

Questions to consider

Is this a complete TRIZ method?

No. This is a practical TRIZ-inspired structuring exercise using contradiction and separation prompts. It does not represent the full TRIZ body of methods or claim a measured effect.
