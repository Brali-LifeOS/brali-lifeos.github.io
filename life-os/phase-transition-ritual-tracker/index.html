Create a Clear Handoff Between Two Activities

Close one mode before starting the next.

Protocol summary · practical

Try this

Choose one recurring transition, write down any unfinished item that must be resumed later, perform one simple closing action in the environment, name the first action of the next activity, then leave the handoff alone unless it proves useful enough to repeat.

Check-in: What did I close, what did I preserve for later, what is the first action in the next mode, and did this handoff reduce avoidable switching friction?

The effective public record is rewritten as a context-handoff checklist: preserve the unfinished state, make one visible closing move, name the first action of the next mode, and keep the handoff only when it reduces practical switching friction.

Transitions become messy when one activity ends without leaving a clear state for later and the next begins without an obvious first action. A short handoff can make the boundary operational: preserve what matters, change the immediate context, and start the next mode deliberately.

1. Choose one recurring boundary

Pick a transition that regularly creates friction: work to personal time, planning to execution, one project to another, meeting to focused work, or another repeated switch. Do not build rituals for every transition at once.

2. Preserve the unfinished state

Write one short note containing the next action, open question, or item that must be resumed later. The note should make re-entry easier without turning the handoff into a new planning session.

3. Make one visible closing move

Use an ordinary action that fits the environment: close the work document, clear the relevant surface, put equipment away, change rooms, or switch the tools needed for the next task. The action is a boundary marker, not a treatment or performance intervention.

4. Name the first action of the next mode

State the first concrete thing you will do next and begin it. After several uses, keep the handoff only if it reduces repeated reopening, forgotten state, or avoidable context switching. Simplify it if the handoff itself becomes friction.

Questions to consider

Does the handoff need a fixed ritual or timer?

No. Use the smallest repeatable sequence that closes the current activity and makes the next one clear. A fixed duration is not required.

What belongs in a work-to-personal-time handoff?

A minimal version can be: record the next work action, close or put away the work surface, and name the first personal activity you are moving to. Add steps only if they solve a recurring problem.
