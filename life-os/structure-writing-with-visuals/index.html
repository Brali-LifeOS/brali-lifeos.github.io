Structure Dense Writing for Fast Navigation

Use headings and visuals only when they answer a reader question.

Protocol summary · practical

Try this

Name the reader's main task, read the current headings without the body, reorganize sections around that path, replace repeated comparisons with a table when rows share the same attributes, use a diagram for relationships or sequence, and keep images only when they show information that prose would make harder to inspect.

Check-in: Can a reader scan the headings and understand the path, and does every visual element answer a question that the surrounding text does not answer as clearly?

The effective public record is rewritten as a document-structure review protocol in which headings, tables, diagrams, and images are chosen only when they answer a reader question or make a relationship easier to inspect.

Visual structure is part of the information architecture of a document. The goal is not to decorate a draft. It is to let readers see where they are, what each section does, and which representation best fits the information.

1. Read the headings as a map

Hide the body and scan only the headings. Reorder or rename them until they describe the reader's likely path through the material rather than the order in which the author discovered it.

2. Give each section one job

Decide whether a section explains, compares, instructs, warns, or documents an exception. Split sections that try to do several unrelated jobs and remove headings that add hierarchy without meaning.

3. Match the representation to the question

Use headings for navigation, tables for repeated attributes, diagrams for relationships or sequence, and images when seeing the thing matters. Keep a text equivalent for information that must remain accessible without the visual.

4. Scan the finished document

Review the page at normal reading width. Check heading hierarchy, labels, captions, table clarity, alt text, and whether any visual element creates maintenance cost without adding information.

Questions to consider

When should I add an image?

Add one when the visual itself carries useful information, such as a location in an interface, a physical arrangement, or a comparison that is hard to describe compactly. Decorative images are optional.

When is a table better than prose?

Use a table when several items can be compared on the same attributes. Use prose when the relationships are irregular or the explanation needs sequence and nuance.

Try it, then review.

Use the action above as a starting point. Adapt it to your situation, notice what happens, and keep, change, or drop it.
