Free library, not a black box

One protocol becomes one inspectable skill.

The skill layer is generated from Brali's trusted protocol feed. It is not a second editorial database.

  • Only reviewed and eligible practical protocols become public skills.
  • Every skill gets a crawlable page, raw SKILL.md, JSON record and SHA-256 checksum.
  • Pending-review and restricted records do not enter the executable catalog.

A Brali verification badge means the format and provenance passed Brali checks. It does not imply endorsement by Anthropic, Nous Research, OpenClaw or another vendor.

Why a skill instead of another prompt library?

A prompt is usually copied once and detached from its source. A skill is a reusable unit an agent can discover when the task fits. Brali keeps that unit deliberately small: one bounded protocol, one check-in, one evidence boundary, one canonical identity.

The open Agent Skills structure is also useful for progressive loading: the host can discover a skill from its name and description, then load the full instructions only when the task matches. Brali does not bundle executable scripts into these protocol skills; they are inspectable instruction files backed by canonical records.

What “verified” means here

Brali CI checks that a generated skill came from the trusted protocol feed, has a valid deterministic name and frontmatter, retains the canonical protocol ID and evidence state, exposes stable links, and matches its published SHA-256 checksum. That is a provenance and integrity check—not a security certification or vendor approval.

Machine-readable Agent Skills catalog

Agents and developers can read /skill-packs/catalog.json without scraping this page. Each catalog entry exposes the raw skill URL, canonical protocol, supported-host hints, evidence state, installation metadata and verification checksum.
