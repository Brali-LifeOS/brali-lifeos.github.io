Brali this week: discoverability, evidence boundaries, and a subscribe path

This week focused less on adding pages and more on making Brali easier to find, easier to follow, and more explicit about what its evidence does and does not support.

AI discovery is explicit

Brali now exposes a fuller machine-readable discovery guide, keeps its read-only data surfaces linked, and allows OpenAI search/user crawlers in robots.txt instead of hiding the public knowledge layer.

Source commit →

Google indexing became a loop

A scheduled Search Console workflow now inspects the live sitemap and rotates URL inspection instead of treating one sitemap submission as the end of search maintenance.

Source commit →

Monthly research has an audit trail

The research scout now produces a monthly digest with reviewed, held, challenged, and watched items. The September digest is deliberately marked partial while the month is still in progress.

September research digest →

Evidence boundaries got narrower

September review work added or strengthened proposals around social-media friction, nutrition planning, vocabulary pretesting, leisure crafting, records maintenance, off-work app boundaries, and sitting breaks while holding back weaker or incomplete claims.

Review decisions →

Updates are now subscribable

Public changes have one canonical manifest that generates RSS for feed readers, JSON Feed for tools, a small update API for agents, and a freshness-focused sitemap for crawlers. No email address or account is required.

RSS → · JSON Feed → · Updates API →

Freshness is a maintenance signal

The update loop checks that a weekly digest does not silently go stale and that the previous month receives a monthly public entry after a short publication window. Staleness becomes a maintenance issue rather than an invisible promise.

Updates hub →

What this does not claim

These changes improve crawlability, subscription, and machine access. They do not prove higher rankings, AI recommendations, traffic, or adoption. Those remain external outcomes to measure rather than infer from implementation work.

Next

  • Keep weekly reports tied to actual repository and evidence changes rather than filler.
  • Publish one monthly synthesis that explains what changed, what was rejected, and what remains uncertain.
  • Use Search Console observations and real agent retrieval tests to decide which discovery gaps deserve product work.
